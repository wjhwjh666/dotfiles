## 3. 学习点和优化项

### 3.1 ✅ 已修：Stop 门禁的输出格式

- **协议事实**：Stop 事件的拦截字段是顶层的 `decision: "block"` 和 `reason`；它的 `hookSpecificOutput` 只接受 `additionalContext`，没有 `blockReason`。exit 2 时即使 JSON 不合 schema 也照样拦截，并用 stderr 当原因。
- **原来的问题**：`l3_stop_gate.py` 输出的是 `hookSpecificOutput.blockReason`，能拦住全靠 exit 2 + stderr，JSON 那一半没起作用。
- **改动**：`l3_stop_gate.py` 改为输出 `{"decision": "block", "reason": ...}`（exit 2 和 stderr 不变）；`l3_regression.py` 的解析跟着改。本机同步见 `reports/sessions/2026-09-25.md` 待办。

### 3.2 🔜 建议：加一个 ConfigChange 守卫（要改 5 个文件，先确认再动）

L3 至今最大的事故是"settings.json 被重置，几周没人发现"。现在的防线：

- 内容守卫：拦 Claude 自己用 Write / Edit 改坏接线；
- SessionStart 自检：**下一次会话开始**才发现并恢复；
- Stop 门禁：只看 PreToolUse 键还在不在。

**会话进行中被别的程序改掉**（比如 2.1.274 修掉的 VS Code 扩展并发写入）这种情况，当前会话发现不了。官方现在有 `ConfigChange` 事件：

- matcher 写 `user_settings`，`~/.claude/settings.json` 一变就触发；
- 返回 `decision: "block"` 后，**新设置不会应用到正在运行的会话**；
- 文档写明：被拦下时**不会给用户或 Claude 任何提示**，只写一行 debug 日志。所以守卫得自己往 `l3-guard.log` 写记录；
- 磁盘上的文件仍然是改过的样子，要靠下一次 SessionStart 自检来恢复。两者分工：ConfigChange 保护当前会话，SessionStart 负责修复。

**上线顺序很关键**：先在 settings.json 里接好 ConfigChange，再把它加进 `EXPECTED_WIRING`。顺序反过来的话，自检会把现有快照判成"不完整"（快照里没有 ConfigChange），直接报 🔴 且无法自动恢复。

要改的文件：新建 `l3_config_guard.py`，以及 `l3_common.py`（`EXPECTED_WIRING`）、`l3_selfcheck.py` 和 `l3_stop_gate.py`（`GUARDS`）、`l3_regression.py`。按 CLAUDE.md "改 >3 文件先摘要确认"，还没做。另外改 hook 前要先读本机记忆里的 `claude-code-hook-protocol-truth`，云端会话读不到它。

### 3.3 🔜 建议：每回合注入的规则里加一句语言规则

[anthropics/claude-code#96326](https://github.com/anthropics/claude-code/issues/96326)（本周新开，标签 bug、platform:linux）报告：读到英文工具输出后，回复会漂成英文，CLAUDE.md 里写了语言规则也拦不住，纠正后也维持不了。

本机 CLAUDE.md 第 1 节要求"面向用户的解释用中文"，但 `l3_rule_inject.py` 的 `RULES` 里没有这一条，而它的设计本意正是"重申没有 hook 能机械拦住的规则"。建议在 `RULES` 末尾加"面向用户的说明用中文"，每回合多十几个 token（估算）；再在回归套件的 `rule_inject_cases` 里加一条关键词检查。

### 3.4 学习点：官方仓库怎么防"备份和本体漂移"

`anthropics/financial-services` 的技能只维护一份，用 `scripts/sync-agent-skills.py` 分发到各个 Agent，再用 `scripts/check.py` 校验清单、交叉引用和同步状态，每个 PR 前都跑。

本仓库的 `claude/` 是 `~/.claude/` 的手工备份，**目前没有任何东西检查两边是否一致**。3.1 的改动在本机同步之前，两边就是不一致的。可以加一个很小的 `scripts/claude-drift.sh`，逐个 `diff` `claude/` 下的文件和 `~/.claude/` 里的同名文件，有差异就列出来。可以放进本机巡检报告里跑。
